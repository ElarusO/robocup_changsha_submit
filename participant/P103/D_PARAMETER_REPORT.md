# 阶段 D：按顺序控制变量微调 PPO 参数

本报告记录 `d-parameter-protocol-v1.json` 规定的有界自动迭代。运行代码为 `run_d_parameters.py`，所有训练、模型导出、动作一致性检查、提交预检及开发集评测均写入 `outputs/P103/d-parameter-control-001/` 和各自独立的 `train-E017` 等目录。

## 方法

以阶段 C 的 1:1 基础/协作混合训练为基线，固定三个训练种子 7101、7102、7103，网络 104→64→64→2、4 个并行场景、PPO 的 `n_steps=512`、`batch_size=256`、`gamma=0.99` 和训练环境实现不变。**训练参数评选只看原始 PPO 导出动作**，不把先前的目标朝向或队友避让混进来。

依次比较：

1. 学习率从 `0.0001` 调低到 `0.00005`，探索系数仍为 0。
2. 学习率从 `0.0001` 调高到 `0.0002`，探索系数仍为 0。
3. 固定前两步筛出的学习率，再单独把探索系数从 0 调到 `0.005`。

每个方向先进行三种子短预算训练，实际 313,344 样本，与 C 在相同步数的对应种子检查点比较。候选必须至少两种子提高、三种子平均加分不少于 5，并且基础组与协作组平均覆盖率均不得下降超过 0.01，才进入下一层。最终只将筛出的一个**已改变**配置扩展到 1,044,480 样本的三种子完整预算，与 C 最终模型同题比较；完整预算也使用相同门槛。`5` 分只是预定的继续投入门槛，不是统计显著性标准。

短预算与完整预算都使用相同的开发验证 v2（100 个不同场景、200 回合）。已经看过的 v3 和 A4 均**不参与训练参数筛选**；A4 保持封存。即便某个配置在 v2 通过，也只能称为开发候选，不自动替换正式 E009。

## 结果

### 相同短预算（313,344 样本）

| 配置 | 7101 | 7102 | 7103 | 三种子均分 | 与本轮对照的平均分差 | 初筛 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| C 基线：学习率 0.0001、探索系数 0 | 116.40 | 117.07 | 116.40 | 116.62 | — | 对照 |
| 调低学习率到 0.00005，探索系数 0 | 103.13 | 108.27 | 105.73 | 105.71 | −10.91（对 C） | 未通过 |
| 调高学习率到 0.0002，探索系数 0 | 126.20 | 123.47 | 115.73 | 121.80 | +5.18（对 C） | 通过 |
| 保持 0.0002，探索系数改为 0.005 | 129.00 | 124.13 | 118.40 | 123.84 | +2.04（对上一行） | 未通过 |

较低学习率三种子均下降，且基础/协作平均覆盖率分别约下降 0.0107/0.0113。较高学习率有两种子提高、平均加分 5.18，基础/协作平均覆盖率分别提高约 0.0031/0.0069，刚过预定门槛。探索系数 0.005 虽使三个种子都略有提高，但相对于“较高学习率且探索系数为 0”的额外平均收益仅 2.04，未达到 +5 门槛。因此只把学习率 0.0002、探索系数 0 扩展到三种子完整预算。

短训练只能判断这些设置在约 31 万样本时的表现：低学习率可能需要更久才起效，不能据此断言它在所有预算下都较差。反复在同一开发 v2 上选择参数仍有选择偏差。

### 完整预算与停止判断

E026–E028 均训练到 **1,044,480** 样本，使用学习率 `0.0002`、探索系数 `0`，并在三个预定位置保存网络及同时刻的归一化统计量。三个最终模型均完成 200/200 回合、`status=ok`，模型导出动作一致性检查和提交预检通过。

| 训练种子 | C 原学习率最终分 | D 高学习率最终分 | 分差 | 基础覆盖率变化 | 协作覆盖率变化 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 7101 | 123.67 | 133.53 | +9.87 | +0.0107 | +0.0067 |
| 7102 | 132.80 | 132.93 | +0.13 | +0.0080 | −0.0080 |
| 7103 | 135.67 | 128.67 | −7.00 | −0.0073 | −0.0067 |
| **三种子平均** | **130.71** | **131.71** | **+1.00** | **+0.0038** | **−0.0027** |

虽然 2/3 种子略有提高，但三种子平均只加 1.00 分，远低于预定的 5 分门槛。固定三个训练种子、按相同开发场景配对重采样的平均分差描述性 95% 区间为 **[−3.67, +5.87]**，跨过 0；这一区间不包含新训练种子带来的不确定性。故**完整预算未通过选择规则，自动流程按协议停止，保留 C 的 `0.0001` 学习率与 `0` 探索系数作为训练基线**。这说明本轮有界参数搜索没有找到稳定的更好配置，不证明 PPO 或项目已达到理论极限。

### 检查是否提前见顶

对三次完整训练中预先保存的中间检查点另行导出并评测，得到：

| 实际样本 | C 三种子均分 | D 高学习率三种子均分 | D − C |
| ---: | ---: | ---: | ---: |
| 313,344 | 116.62 | 121.80 | +5.18 |
| 626,688 | 126.47 | 126.62 | +0.16 |
| 1,044,480 | 130.71 | 131.71 | +1.00 |

D 高学习率自身的平均分从 121.80 持续升到 131.71，**没有出现训练后期分数下跌**；真正缩小的是它相对原学习率 C 的领先幅度。它更像“前期学得快”，而非“最终能学得更好”。同种子短训练 E020–E022 与完整训练 E026–E028 的第一个检查点，导出 `.npz` 包内各项数值数组完全相同（最大绝对差为 0）；不同 `.npz` 文件的整体 SHA-256 不同，故不能仅用压缩文件摘要判断数值权重是否一致。

全部短训练与完整训练原始记录在 `../../outputs/P103/d-parameter-control-001/progress.json`，成对汇总与区间在 `../../outputs/P103/d-parameter-summary-001/summary.json`；中间检查点逐次结果在 `../../outputs/P103/d-param-mid-v2-E026-313344/` 等六个独立目录。正式提交模型仍为 E009，A4 最终确认集未用，本地 Windows 成绩不代表组织方核验。

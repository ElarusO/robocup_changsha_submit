# P103 开发知识地图：从看懂项目到独立做实验

> 整理日期：2026-09-29。面向已有 C/Python 基础、参加过机器人比赛，但刚接触完整机器学习项目的学习者。这里整理的是**本次开发实际涉及或下一步直接需要的知识**，不是要求先学完一整门机器学习课程。先读“是什么”，再打开所列代码和实验记录核对。本文是学习大纲，不是新的实验结果或正式成绩。

## 0. 先建立一张全局地图

本题要让 3 台机器人在 10 步内持续覆盖 3 个移动目标，同时减少机器人碰撞。每台机器人在正式运行时只看自己的局部观测，输出二维动作。当前正式 P103 模型是 **E009**：训练时使用 PPO，正式推理时用 NumPy 读取 `artifacts/policy.npz`。开发过 E015 等候选，但按事前 A4 换模规则仍保留 E009。公开分数、开发分数、A4 分数都是本地结果，组织方核验分数尚未知。[赛题规程](../../competitionv1.2.md) · [当前报告](REPORT.md) · [A4 决策](F1_A4_REPORT.md)

```text
官方环境生成场景
  → 每台机器人取得局部观测
  → 训练时：展平、归一化、PPO 更新网络
  → 导出：网络参数和归一化统计写入 policy.npz
  → 正式推理：entry.py 读观测、计算动作
  → 官方评测：推进物理环境、记录覆盖与碰撞、汇总分数
  → 实验记录：保存代码版本、模型摘要、配置与结果
```

最重要的区别：**训练**会改变网络参数；**推理**只用已保存的参数算动作；**评测**让策略在场景中运行并计分。训练环境可以安装 PyTorch 等工具，正式推理所需的依赖必须单独核对。

## 1. 比赛任务与评分：先弄清“优化什么”

| 知识点 | 简单解释 | 本项目要弄懂什么 |
| --- | --- | --- |
| 回合与时间步 | 一个回合是连续运行的一段场景；每推进一次是一步 | 公开套件每回合 10 步。覆盖目标后仍继续运行，保持覆盖也会得分。 |
| 移动目标与局部观测 | 目标会移动；机器人不能直接读取所有机器人的完整世界状态 | 正式 `act()` 只能使用当前机器人的合法观测和允许保留的自身历史。 |
| 覆盖 | 机器人进入目标覆盖半径，该目标在这一时间步算被覆盖 | 本题是**持续覆盖目标**，不是清扫场地面积。一个机器人同一步最多贡献一个目标的覆盖。 |
| 碰撞 | 两个机器人发生重叠接触，会产生碰撞惩罚 | 追目标更快可能同时增加碰撞；只报总分会掩盖问题。 |
| 团队奖励 | 全队共享的单步表现 | 每步可理解为“覆盖比例 − 0.2 × 碰撞参与比例”；不能把每台机器人拿到的同一团队奖励重复累加。 |
| 分组评分 | 基础组与协作组分别统计，再等权合成 | 比较策略时同时看两组得分、覆盖率和碰撞率。不同套件的总分不能直接相减来证明进步。 |

**应能自己回答：**如果 3 个目标中某一步只覆盖 1 个、没有碰撞，覆盖率是多少？如果机器人晚一步才进入覆盖半径，为什么 10 步平均成绩会下降？阅读[规程第 8、17 节](../../competitionv1.2.md)和[评分实现](../../coverage_bench/scoring.py)。

## 4. 读懂代码结构与接口契约

从以下顺序读代码，先抓数据流，再看细节：

1. [`submission.yaml`](submission.yaml)：参赛编号、入口、模型路径、摘要和字节数。这是“交付清单”。
2. [`entry.py`](entry.py)：`build_policy(context)` 建策略实例；`reset()` 开始新回合；`act(observation)` 算动作；`close()` 释放资源。
3. [官方协议](../../coverage_bench/protocol.py)：规定传给策略的对象与方法签名。代码能运行，还必须符合这个接口。
4. [观测展平](../../coverage_bench/spaces.py)：把观测字典按固定顺序变成数字向量；P103 的网络输入为 104 维。
5. [`train.py`](train.py)：构造训练环境、运行 PPO、保存检查点。它与正式入口是不同代码路径。
6. [评测指南](../../docs/how_to_use.md)：先预检，再公开评测；读取 `status`、错误、回合数后才解释分数。

**接口契约**就是双方约定的输入、输出和调用时机。这里动作必须是两个有限浮点数，合法范围为 `[-1, 1]`；每台机器人独立调用，不应靠共享可变内存交换秘密信息。阅读代码时尝试画出“观测字典 → 104 维数组 → 归一化 → 网络 → 二维动作”的箭头图。

## 5. 多智能体、部分可观测与机器人控制

| 知识点 | 通俗理解 | 与本题的关系 |
| --- | --- | --- |
| 智能体（agent） | 一名独立做动作的机器人 | 3 台机器人都可以使用同一组网络参数，但每台只收到自己的观测。 |
| 状态与观测 | 状态是整个世界的真实情况；观测是机器人被允许看到的一部分 | 训练时可能有更丰富信息，正式执行不得偷读不可见目标或其他机器人的内部状态。 |
| 部分可观测决策 | 看不到全部世界，只能据当前信息和合法记忆决策 | 目标不在视野中时，不能假设知道其真实位置；存在标记、可见标记不能混淆。 |
| 共享参数与局部执行 | 多台机器人复用同一策略函数，但分别运行 | 不意味着它们能自动分工；同一策略可能使多台机器人争抢同一目标。 |
| 位置、速度、加速度、阻尼 | 机器人不会在给出动作后瞬间抵达目标；速度和惯性影响下一步位置 | 只看“方向对不对”不足以判断覆盖；动作幅度变小可能刚好错过覆盖半径。 |
| 动态目标与预测 | 目标也会运动；追当前坐标可能发生滞后 | 改进策略时应把目标速度和相对运动纳入轨迹分析，同时遵守局部观测限制。 |
| 避碰与分工 | 要兼顾接近不同目标和机器人之间的安全距离 | P103 的协作组曾出现连续碰撞，添加避让规则能消除部分碰撞，但不保证总分提高。 |

**应能自己解释：**为什么“始终朝最近目标跑”不一定最优？为什么机器人靠近同一目标会降低团队覆盖？参考[分组弱点分析](GROUP_WEAKNESS_ANALYSIS.md)和[轨迹跟进](D_TRAJECTORY_FOLLOWUP.md)。

## 6. 神经网络与强化学习：弄清“模型怎样学”

### 6.1 神经网络最小知识

- **向量、矩阵与形状：**观测是 104 个数，动作是 2 个数；权重矩阵把一层数值变成下一层。矩阵维度不匹配就无法计算。
- **多层感知机（MLP）：**P103 是 `104 → 64 → 64 → 2` 的前馈网络；没有图像识别模块。前向传播是连续的矩阵乘法、偏置和非线性变换。
- **参数与模型文件：**权重、偏置是学习到的数字；`policy.npz` 还保存观测归一化所需统计量。模型文件不是一段“会思考”的程序，必须由 `entry.py` 按正确格式计算。
- **确定性动作：**评测时给定相同模型与观测，应得到相同动作；训练时会有探索和随机采样。P103 导出时比较了 SB3 与 NumPy 在同一批观测上的动作。

### 6.2 强化学习最小知识

| 术语 | 简单解释 | P103 实例 |
| --- | --- | --- |
| 策略（policy） | 从观测到动作的函数 | `entry.py` 的 `act()` 是正式策略。 |
| 奖励与回报 | 每步的评价；多步奖励构成回报 | 覆盖与碰撞影响团队奖励。训练辅助奖励若新增，必须与官方评分分开记录。 |
| PPO | 一种逐批收集轨迹、按约束幅度更新策略的强化学习算法 | 当前训练使用 Stable-Baselines3 PPO；正式推理不需要 SB3。 |
| rollout | 先运行一段环境，收集观测、动作、奖励等数据再更新 | `n_steps=512` 与并行环境数共同影响每轮实际采样量。 |
| 价值函数（critic） | 估计从当前状态往后还能得到多少奖励 | 时间到期和真正任务终止的处理不同，漏掉结束观测会影响学习目标。 |
| 折扣因子 `gamma` | 对较远未来奖励的重视程度 | P103 使用 `0.99`，但不能仅凭该数推断成绩。 |
| GAE `gae_lambda` | 综合不同时间跨度的信息来估计动作好坏 | P103 使用 `0.95`；理解它解决“奖励有噪声”即可，先不必推导公式。 |
| 学习率 | 每次参数更新的幅度 | D 阶段调高学习率，短训练更快，完整预算平均仅多 1 分。 |
| 探索系数 `ent_coef` | 鼓励策略保留动作多样性的权重 | P103 比过 0 与 0.005；不能把短期增益直接当最终增益。 |
| 训练种子 | 初始化、采样等随机过程的起点 | 比较训练方法至少看多个种子，不能只挑最好的一次。 |

**应能自己解释：**为什么请求训练 100 万步，保存时可能是 1,044,480 样本？为什么“训练更久”或“学习率更高”不保证得分更高？参考[训练报告](REPORT.md)、[B 阶段重复实验](B3_B4_REPORT.md)、[参数对照](D_PARAMETER_REPORT.md)。

## 7. 训练数据通路：本次最值得亲手追踪的一条链

```text
场景 reset(seed)
  → 多机器人观测字典
  → 展平为固定顺序的 104 维向量
  → 用训练统计量做 VecNormalize
  → PPO 输出动作、环境 step
  → 收集奖励、结束标记、终局观测
  → 更新策略并保存网络与归一化统计
```

需要理解四个容易出错的地方：

1. **随机种子要传到每次重置。**首次回合可复现，不意味着自动开启的下一回合也可复现。A2 修复了自动重置时的种子链。
2. **训练与推理必须使用同一观测顺序。**即使都恰好是 104 个数字，字段顺序不同也会让模型“认错数”。
3. **时间截断不等于真正终止。**到了预定第 10 步，要保留结束时的观测和截断标记，价值函数才能正确处理。
4. **归一化统计是模型的一部分。**只保存网络权重、丢掉均值和方差，推理动作就可能改变。

特别注意：正式 E009 是 **A2 修复前**训练出的历史模型。A2 修复改变了以后新实验的训练通路；用当前 `train.py` 和相同参数重训，不能称作 E009 的逐字节复现。[A2 审查](A2_AUDIT.md)

## 8. 模型导出与正式推理：保证“训练出来的动作没被翻译错”

- **导出**：把训练框架中的策略网络参数和观测归一化统计写为 NumPy 可读取的 `.npz`。这一步连接训练世界与正式运行世界。
- **一致性检查**：对同一批真实观测，分别用训练框架和正式 `entry.py` 计算动作，再比较最大差值。P103 的 E009 曾在 256 条观测上做到最大差约 `3.604e-07`；这是导出正确性的证据，不是策略分数。
- **清单校验**：`submission.yaml` 的模型路径、SHA-256、`size_bytes` 要与磁盘文件一致；改模型后必须重新登记。
- **最小推理依赖**：正式入口当前只需 NumPy 和官方协议实现；训练用的 PyTorch、SB3 不应成为正式推理的隐含前提。
- **安全加载与资源限制**：正式环境断网、限时，不能依赖外部下载、不安全反序列化或未登记文件；提交预检还会扫描本人目录中的训练与实验 Python 源码。

**应能自己完成：**指出 `entry.py` 从哪里读模型、怎样计算动作；说明模型 SHA-256 和 Git 提交号分别标识什么。[入口代码](entry.py) · [交付核对](F2_FORMAL_DIRECTORY_AUDIT.md)

## 9. 评测结果怎样读：先判断有效，再看分数

一份评测通常包括 `result.json`（总体状态与分组指标）、`episodes.csv`（逐回合数据）以及耗时记录。阅读顺序应为：**提交和模型摘要 → 套件/种子版本 → `status` 与错误 → 成功回合数 → 分组覆盖/碰撞 → 总分**。运行失败时不能只挑成功回合求均分。

| 测试类型 | 用来做什么 | 不能据此声称什么 |
| --- | --- | --- |
| 官方公开套件 | 检查接口、运行状态、快速观察表现 | 只有少量场景，不能据此预测隐藏测试排名。 |
| 开发验证 v2/v3 | 同场景比较候选、分析分组和失败轨迹 | 已反复用于选择，不能当完全独立的最终证据。 |
| A4 最终确认集 | 对冻结 E009、E015 两包按事前门槛做一次同场景比较 | 已被读取；之后不能反复用它调参还称其为未见测试。 |
| Ubuntu 虚拟机检验 | 检查 Linux 依赖、运行行为及与 Windows 的一致性 | 不是组织方最终容器或隐藏场景。 |
| 组织方核验 | 官方按冻结提交和私有测试统一评分 | 目前尚未取得，不能填写或推测成已得成绩。 |

**本次例子：**E009 公开套件 200.00；开发 v2/v3 125.33/119.67；A4 120.33。数字不同主要因为**测试场景不同**，不能说同一模型突然退步。E015 组合在 A4 为 126.33，比 E009 高 6.00，但没有达到事前规定的全部换模条件。[F1 报告](F1_A4_REPORT.md) · [Linux 记录](LINUX_VM_CHECK.md)

## 10. 实验设计与统计：避免“偶然高分”

| 知识点 | 怎样理解 | 本次实际教训 |
| --- | --- | --- |
| 基线 | 一个固定的比较起点 | E009 是正式回退模型；B、C、D 各有自己的同条件比较基线。 |
| 控制变量 | 一轮只改变一个明确因素 | 比学习率时固定训练种子、预算、场景与网络；否则无法归因。 |
| 配对比较 | 两策略跑同一批场景和种子，再算逐场景差 | 比分别看两个总分更能减少场景难易造成的干扰。 |
| 多训练种子 | 重新训练几次，观察方法是否依赖幸运初始化 | 三个种子的均分不是一份可以提交的“平均模型”。 |
| 独立场景与重复回合 | 相同场景重复两次不等于多出两个独立场景 | v2/v3 各有 100 个不同场景、200 回合；重采样以场景为单位。 |
| bootstrap 区间 | 从已有场景反复抽样，估计结果对场景选择有多敏感 | A4 的 E015−E009 区间 `[−0.33, 13.00]` 跨 0；不能说在这批场景抽样下稳定领先。 |
| 事前门槛 | 看分数之前先写下如何决定是否继续或换模 | A4 虽 +6 分，却因区间下界未大于 0 而保留 E009；不能事后降低门槛。 |
| 选择偏差与数据泄漏 | 在同一题上反复挑最好方案，结果会显得过分乐观 | 用过 v2/v3/A4 的分数指导修改后，要如实标记它们已参与开发。 |
| 失败分析 | 追踪局部失分机制，而不是只看总分 | E016 的目标朝向混合让动作减弱、晚一步覆盖；E3 修复该轨迹但整体未过门槛。 |

## 12. 工程交付、合规与可复现

- **本人目录边界**：参赛代码与文档只改 `participant/P103/`；官方 `coverage_bench/`、`configs/`、`scripts/` 用来阅读和调用，不因想提高分数而改动。[仓库约束](../../AGENTS.md)
- **提交前预检**：检查目录名、`participant_id`、入口、模型清单、依赖和源码扫描。预检通过只说明提交结构和部分规则通过，不说明性能更好。[使用指南](../../docs/how_to_use.md)
- **实验可追溯**：每个重要尝试记录假设、唯一变动、训练种子、实际样本、模型摘要、代码版本、套件版本、成功回合数、分组指标与失败原因。[LOG.md](LOG.md) · [experiments.csv](experiments.csv) · [REPORT.md](REPORT.md)
- **独立输出目录**：新实验使用新路径，例如 `outputs/P103/eval-001`、`eval-002`，不要覆盖旧原始数据。`outputs/` 通常被 Git 忽略，应另备份。
- **许可证和第三方来源**：说明哪些代码自己写、哪些沿用官方模板、用了哪些第三方库或模型；本人目录已有 [LICENSE](LICENSE) 和 [THIRD_PARTY.md](THIRD_PARTY.md)。
- **最终提交**：区分私有日常推送、公开 Fork 分支和向官方仓库开的 Final Submission PR。PR 由组织方核验；本地成绩不等于正式成绩。时间窗口和最终细则以组织方最新公告为准。[赛题规程](../../competitionv1.2.md)

## 13. 建议的学习顺序和验收办法

不用同时读完所有源码。每一轮做到“能用自己的话解释、能在文件中定位、能用一条已有记录举例”即可。

1. **第 1 轮：任务与文件。**读第 0、1、4、9 节；能说明机器人看什么、做什么、怎么算分，指出正式模型和入口。
2. **第 2 轮：环境与 Git。**读第 2、3、12 节；能分清 Python 解释器、运行结果、Git 提交、备份与 PR。
3. **第 3 轮：模型和训练。**读第 5–8 节；沿一次 `reset → act → step` 画出数据流，解释 PPO 与 NumPy 推理的分工。
4. **第 4 轮：实验方法。**读第 10、11 节；挑 E3 或 A4 报告，说清假设、固定了什么、改变了什么、为何停止。
5. **第 5 轮：独立设计。**提出一个只改 P103 文件的单因素设想，先写测试场景、比较对象、停止/换模门槛、记录格式；真正运行前再确认不会覆盖旧结果。

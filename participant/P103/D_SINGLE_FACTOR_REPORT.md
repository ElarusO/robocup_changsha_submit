# D 阶段：两类弱点的单因素改进实验（2026-09-26）

## 要解决的问题与实验设计

C 阶段的逐场景诊断发现两类值得追踪的轨迹：基础组 `v2b-02` 中，机器人后半程漏掉可见目标；协作组 `v2c-07`、`v2c-09` 中，机器人靠近时连续碰撞。因此只试两种**互相独立**的推理动作修正，不重新训练网络：

1. **目标朝向 `target`**：看见目标时，找最近一个目标，把原动作的 40% 换成指向该目标的单位方向；看不见目标时动作不变。目的是减少漏目标。
2. **队友避让 `avoid`**：看见队友且距离小于 0.30 时，给原动作加远离队友的斥力；范围外动作不变。目的是减少碰撞。

对 C 阶段固定的 E014、E015、E016 三份最终模型，各制作两份临时提交副本。每个副本保留原网络权重，只启用上述一种修正，分别在相同的开发验证 v2（基础/协作各 50 个场景、每场景重复 2 次，共 200 回合）上评测。基线直接使用此前完成的原模型评测，按模型与场景配对。运行前冻结的协议见 `d-single-factor-protocol-v1.json`，实现见 `single_factor_policy.py`，运行与汇总脚本见 `run_single_factor.py`、`summarize_single_factor.py`。全部使用独立的 `outputs/P103/d-stage-*`、`d-check-*`、`d-v2-*` 目录。

六次临时提交预检均无拒绝项；评测均 `status=ok`、200/200 回合完成，结果为 Windows `local_preview`。分数和覆盖率、碰撞率均来自评测 `result.json`，按场景的细项来自 `episodes.csv`。完整汇总在 `../../outputs/P103/d-single-factor-summary-001/summary.json`，另有 `paired-models.csv` 与 `focus-cases.csv`。

## 原先关注的轨迹

- `v2b-02`：目标朝向对 E014、E015 的平均覆盖率分别提高 0.0333、0.0667；E016 却下降 0.0333。队友避让对该场景覆盖率没有影响。这一局部问题有改善，但并未跨三模型一致解决。
- `v2c-07`：队友避让使 E014 的该场景平均碰撞率下降 0.20；E015、E016 在这一场景原本就没有可再降低的碰撞。目标朝向的该场景碰撞率不变。
- `v2c-09`：队友避让使三份模型的该场景平均碰撞率都下降 0.20；其中 E016 的平均覆盖率下降 0.0333。这说明原来反复接触的轨迹消失了，同时可能有绕行代价。

这些场景是**从同一开发集诊断后挑出**的，主要用来解释行为，不是独立验证。整体结论以 200 回合全开发集为主。

## 按预定规则判断与下一步

协议事先规定：目标朝向需至少 2/3 模型提高基础覆盖率、三模型平均分下降少于 5 分、协作碰撞率平均上升不超过 0.005；队友避让需至少 2/3 模型降低协作碰撞率、平均分下降少于 5 分、基础覆盖率平均下降不超过 0.01。**两种改动都通过这一初筛**。目标朝向 2/3 模型提高基础覆盖率，平均加分 6.67；队友避让 3/3 模型降低协作碰撞率，平均加分 0.11。

下一轮优先研究目标朝向为何损害 E016 的基础覆盖率，例如记录朝向介入次数、目标距离和原动作方向，并在新的开发场景或训练种子上验证。队友避让可以作为减少碰撞的候选机制，重点检查绕行导致的覆盖损失。**目前没有测试两种改动的组合**，因此不能把各自收益相加，也不能据此替换正式提交模型。反复使用同一 v2 选择方法会产生选择偏差；最后仍需预先确定候选，再按 A4 独立确认流程评估。
